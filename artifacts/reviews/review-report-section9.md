  The README claims that the DNS lookup can be cancelled. The code does not
  cancel it.

  The default resolver is resolve_hostname. It calls socket.getaddrinfo,
  which blocks. The resolver accepts no cancel_event. After a timeout,
  future.cancel() has no effect on a thread that is already running. A
  stalled lookup therefore keeps one of the 8 dns_resolver threads busy
  until the OS resolver returns. If 8 lookups stall at the same time, new
  lookups wait in the queue. Each queued lookup then times out, even when
  its host would resolve. Change the docs to say that the timeout bounds the
  caller's wait but does not stop the lookup. Another option is to use a
  resolver that can actually be cancelled, such as an async DNS library.

  Synchronous validation can block for the full deadline, and failures other
  than OS errors escape unwrapped.

  future.result(timeout=...) raises concurrent.futures.TimeoutError. In
  Python 3.11 and later, that class is an alias of the builtin
  TimeoutError, so the timeout branch works. Any other exception from the
  resolver, such as RuntimeError, propagates without wrapping. The async
  path wraps the same exception as TransientDNSError, so the two
  validators behave differently. Add except Exception that wraps the error
  as TransientDNSError, or extract a shared helper so both paths behave
  the same.
